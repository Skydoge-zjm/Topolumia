# 决策：MCP 封装 CLI，科研规则留在领域服务

状态：采用，当前主链路已实现。

研究者优先使用本机编程型 Agent，同时需要统一科研对象语义、会话范围和后续团队权限。MCP 提供结构化发现和宿主接入；CLI 承担可独立执行的命令；HTTP 与领域服务维持一致科研行为。

不维护一套 MCP 写入实现和另一套 CLI 写入实现。MCP 内部调用 CLI，二者复用合同与同一 HTTP 服务。权限在多入口和领域层共同检查，不能把“协议提供治理”理解成协议天然实现全部授权。

代价是多进程调用和更多故障边界。通过共享 Schema、明确错误、受控并发、幂等与分阶段读取控制，而不是再叠加一套面向模型的通用函数接口。

CLI 对新内部系统并非天然零上下文成本。常规工具动作必须开箱明确，复杂细节才按需披露；评估应覆盖目录、Schema、正文、失败和重试，不能套用未经复现的行业 token 比率。

机制：[Agent 接入](../architecture/agent-integration.md)。远程 MCP 仍未交付，不由本决策推断为已经支持。
