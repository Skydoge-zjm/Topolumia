# 科研对象、逻辑拓扑与时间记录

科研节点是可持续积累、引用、复查和连接的研究对象。节点组把相关对象组织为一个也能被引用和连接的集合；两者共同组成科研拓扑。科研对象可以在研究推进中逐步丰富。

## 节点的不同层次

| 层次 | 含义 |
| --- | --- |
| 系统身份 | 项目、对象 ID、类型、创建者、状态与版本，使对象可导航、授权和追溯 |
| 类型核心 | 该类型稳定的最小结构；例如文献的论文标题、作者和标识 |
| 自由内容 | 用户自行创建、命名、排列的内容块，承载解释、数字、表格、图片和材料 |
| 来源与表示 | 内容依据何处、原文件及可读表示之间的关系 |
| 拓扑关系 | 对象之间的支持、比较、依赖等逻辑联系 |

类型核心与自由内容互补。不同节点应体现类型语义；开放内容块不意味着所有节点都成为同一种通用文档。核心字段存在不意味着全部必填。

## 三类节点

顶层节点按研究对象的结构与专属能力划分，只设文献、实验、研究笔记三类。

| 类型 | 代表什么 | 主要内容 |
| --- | --- | --- |
| 文献 | 一项外部研究工作及围绕它积累的阅读成果 | 书目信息、原文、方法理解、图表与评价；详见 [文献节点](literature-node.md) |
| 实验 | 能够记录、复现某项或一组具体结果的实验单位 | 复现条件、执行过程与结果；同一实验可包含多次 run，相关实验可组成节点组 |
| 研究笔记 | 一份可独立引用、连接和修订的研究内容 | 问题、想法、假说、假定、观察、推论、结论、证据缺口、综合分析与决策依据 |

研究问题由研究笔记承载，可以独立成节点，持续关联文献、实验、候选解释和回答依据。阅读笔记也使用研究笔记；围绕单篇文献的局部理解可直接保存在文献内容块中，跨来源综合或需要独立引用时可建立笔记。

研究者决定内容是否独立成节点。文献、实验与节点组都能拥有自己的正文，不要求每段观察、解释或总结都额外建立笔记，也不预设三类节点的研究顺序。

当前交付范围见 [工作区需求](../requirements/research-workspace.md)；精确代码类型以 [节点种类定义](../../../src/domain/research/node-kinds.ts) 为准。

## 研究笔记

研究笔记以标题和默认正文作为起始写作区，用户可以直接写作，并按需要添加、命名和排序多个自由内容块。

笔记采用可选的自由标签，供识别、搜索和筛选。用户可以填写问题、观察、总结或研究主题等标签；系统不另设固定的内容性质分类，也不根据标签规定正文栏目或推断科研结论。

## 实验与 run

一个实验节点代表一个可记录、复现具体结果的实验单位。例如“将 LoRA Rank 设置为 4 后在某一数据集上的微调实验”，可以产生训练完成后的三个图像指标。多个指标可以共同描述这项实验的一组结果，无需分别建立科研节点。

run 是完成或复现该实验的一次执行尝试。同一实验可以包含多个 run，包括失败、重试和再次复现；失败或重跑不改变实验节点的身份。每组结果应能追溯到对应 run 及其执行条件，保留复现条件、执行过程与结果之间的对应。

实验身份不要求每次 run 的全部配置完全相同。例如，同一项微调实验中，batch size 为 32 的 run 因显存不足失败，调整为 16 后再次执行，可以继续归入同一实验；应保留各次实际配置与失败情况。

### 实验材料、过程与最终结果

Topolumia 通过内容块组织和呈现实验的复现材料、过程记录与最终结果。用户沿用自己的实验执行方式；平台不承担参数控制和一键启动，也不要求训练程序接入另一套 Topolumia 记录 SDK。

| 阶段 | 内容与行为 |
| --- | --- |
| 实验前 | 按需以内容块保存配置文件、脚本、代码片段、命令、版本信息及其他复现材料。上传的文件保存当时内容，科研项目目录中的原文件后续改变仍可回溯已保存材料 |
| 实验中 | 接入 W&B、TensorBoard 等实验记录生态，读取其原有记录文件或数据，在工作台内渲染训练过程和指标曲线，保留对应来源；查看实验过程无需跳转到提供商页面 |
| 实验后 | 通过指标、表格、TeX 表格及其 PDF 表示等内容块保存最终数据与概要，便于后续分析，并保留与执行记录的对应 |

以上阶段说明材料用途，不要求固定栏目、固定配置字段或每阶段必须创建内容块。不同配置与代码管理习惯通过可扩展内容块表达；原始材料和可读表示共同保留。

人和 Agent 使用同一份过程记录与结果。曲线除视觉展示外，需要提供可读取的对应数据与来源，便于分析；最终指标保留其条件和出处。

### 一个内容块容纳多个 run

内容块按材料用途自由组织，一个块可以包含多个 run；同一次 run 的材料也可以分布在多个块中。无需为每次 run 复制一套固定栏目。

| 内容块示例 | 组织与展示 |
| --- | --- |
| 训练曲线 | 用户选择“实验记录—W&B”并导入三个 run，各自包含四个指标。该块按指标展示四幅交互式曲线图，每幅图叠加三个 run 的对应曲线，保留来源和 run 区分 |
| 实验配置 | 一个块通过一张表或三份 YAML 文件记录三个 run 的配置，保留原始材料及各次差异 |
| 终端日志 | 一个块保存三份终端日志原文件，并能明确每份日志对应的 run |

实验内部维护统一的 run 清单，各内容块引用同一次执行的共同身份。例如，导入 W&B 记录后识别出三个 run，配置文件、表格中的记录和终端日志可以分别关联到其中一次执行；同一 run 在多个块中出现仍是同一个 run。

实验节点提供内容块之间的材料关联能力。例如，某份 YAML 文件或配置表中的某条记录，对应训练曲线块中的哪个 run；日志也可以关联同一次执行。关联需要表达到具体材料项，不能只知道两个内容块整体相关。

这些关联表达实验内部的材料与执行对应；节点之间的科研逻辑关系继续由拓扑有向边表达。

### 跨实验关联查看

用户可以从不同实验节点选择具体 run 进行比较。例如，选择节点 A 的 run 3 与节点 B 的 run 1，将相同记录项的曲线叠加到同一张图中，并保留实验、run 与来源的区分。

无论由人还是 Agent 发起，比较都是临时查看，不保存为比较对象或对比内容块，也不合并实验或改写原始记录。需要保存分析时，由人或 Agent 在新建的研究笔记节点中记录；Agent 写入仍遵循候选与人工审批规则。

初版曲线叠加仅支持名称完全相同的指标，内容块内与跨实验比较采用相同规则；不提供不同名称指标的对应选择或语义匹配。其他曲线展示与对齐细节暂缓设计。

run 的显示名称不作为执行身份；不同执行可以重名。相同记录源重复出现在多个块中时引用同一 run，也可由用户明确选择对应的已有 run。原始文件的归档与可变的服务来源应明确区分；记录源的可用范围与刷新能力见 [实验与来源模块](../../technical/modules/experiments-and-sources/README.md)。

## 节点类型、标签与研究关系

节点类型决定基本结构与专属能力，自由标签用于描述和检索内容。节点之间的关系通过拓扑中的有向边显式建立；节点类型、标签及创建入口不预先决定对象之间的关系。详情页的新建笔记等便捷入口属于前端交互，不改变上述领域边界。

假说、前提假定和结论等研究语义需要结合具体论证理解。某份笔记中的陈述可以作为实验 A 的前提，同时成为实验 B 的检验对象；竞争假说通过解释之间的竞争或替代关系表达。支持、反驳、检验、采用为前提等关系记录对象在具体研究中的作用，不能仅从一个全局类型或标记推断。

观察需要保留来源、条件和不确定性；推论需要保留依据与推导；结论需要保留适用范围。统一为研究笔记不取消这些内容差异，标记或候选接受状态也不表示科学结论已经得到验证。

下一步行动使用活动记录中的行动项，并关联相关科研对象；决策的执行安排同样进入活动记录，需要独立引用的决策依据可保存为研究笔记。节点组继续承担集合、层级与组织职责，见下文。

## 自由内容的边界

系统预定义内容块类型及处理能力；研究者决定标题、数量、顺序和材料形式。“Table 2 指标”可以是数字、结构化表格、XLSX、TeX、截图或链接，不要求同时具备所有形式。

同一内容可具有原文截图、人工转录表格和来源链接等多种表示。可计算数据与原始证据需要分开识别，转录不能抹掉原文。图表、指标的条件与来源也是研究内容，不应在编辑时被默默丢弃。

## 节点组

节点组采用一种统一概念：可以只保存名称和成员，也可以增加成员角色、自由材料与连接整个组的正式关系。整理、筛选和折叠是它的基础能力，无需将简单集合与有研究语义的集合分为两种对象。

组本身有稳定身份。实验设计→实验组→实验总结可以直接连接组；展开后保留组入口，成员节点仍然独立。可各选一条主入边和主出边，但不限制其他真实关系。

一个节点可属于多个组，组可形成无环层级。成员与父子关系表达集合范围，科研逻辑边表达支持、比较、检验等联系，两者独立。收起是显示投影；多组共享成员不能通过任意分配改变其科研归属。

组删除保留成员和子组，正文与历史仍按生命周期追溯。完整规则见 [节点组业务](node-groups.md)，当前交付差距见 [节点组需求](../requirements/node-groups.md)。

## 研究记录

研究记录是一级时间视图，包含两类互补内容：

- 自动科研历程：创建、修改、删除节点或内容，提出、修订、接受、拒绝候选等真实领域行为，区分人和 Agent。
- 活动纪要：组会、阅读、复盘及周期活动，保存时间、参与者、内容、决策、行动及相关节点。

定期组会是时间活动，不因每月召开而成为拓扑链条。纪要可以引用节点、促成新节点，但活动与科研对象保持不同身份。

Agent 消息、工具调用与 MCP 审计是执行记录，不能代替科研历程。普通科研笔记可以由用户保存，但自动记录完整回复不等于记录了一次有效科研进展。

实现与目标入口：[节点模块](../../technical/modules/research-nodes/README.md)、[节点组模块](../../technical/modules/node-groups/README.md)、[研究记录模块](../../technical/modules/research-records/README.md)。
