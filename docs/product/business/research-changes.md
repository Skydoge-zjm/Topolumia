# 科研变更、候选与确认

正式科研对象表达项目当前采用的研究内容；候选表达一份尚待处理的建议。候选中分配的对象 ID 可用于继续编辑和预览，并不意味着对象已进入正式拓扑。

## 人和 Agent 的写入

有权限的人在科研对象页面编辑，是明确的直接修改操作。节点及节点组的核心、成员、正文和关系均受同一变更规则约束。Agent 通过科研接口提出候选，由有权限的人接受、拒绝或暂缓。两者最终使用同一套版本校验和持久化机制。

原生工具权限批准的是执行行为，例如修改文件或运行命令；科研审批批准的是内容进入项目。两种批准互不替代。

## 候选的语义

- 包含原因、具体研究内容、来源和修改范围，能够预览，能够增量修订。
- 未接受的候选与正式对象分开读取；不能把候选预览标作正式成果。
- 接受时检查当前权限、对象版本与资产可用性；冲突必须显式解决，不能静默覆盖。
- 接受、拒绝和暂缓记录具体操作者及结果，Agent 无权自行完成这些审批。
- 同一请求重试应复用幂等标识；重新研究或改变输入不应冒用旧请求。

## 删除

删除科研节点或节点组是科研变更，需要权限、原因、观察到的版本以及实际影响的确认。关联关系随删除处理，并更新受影响对象版本；历史与活动引用仍应能解释曾经发生的行为。

从组移除成员只解除成员关系，删除组保留成员节点；层级与关联处理遵循 [节点组规则](node-groups.md)。拒绝候选、删除对象和隐藏会话分别作用于不同对象。
