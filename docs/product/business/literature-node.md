# 文献节点的语义

文献节点代表一项论文工作及研究者围绕它积累的阅读成果。显示名称可以是 SR3 这样的常用名，论文正式标题仍独立保存。

## 稳定核心

节点名、论文标题、作者、年份、会议或期刊、领域、DOI/arXiv 等标识、原文链接、摘要和标签属于文献核心。最小身份之外的信息允许未知；缺少作者或会议不应阻止先保存研究成果。

核心保留类型特征，供列表、检索、书目和引用使用。确切字段与必填规则见 [核心 Schema](../../../src/domain/research/content-blocks.ts)，不在文档复制第二套字段合同。

## 阅读成果

研究者可以自由创建“算法图”“实验设置”“与本项目的区别”等内容块。系统不要求固定的“贡献、方法、实验、局限”栏目，也不把这些标题作为校验条件。

Agent 完成“阅读并整理论文”任务时，只有书目信息通常不满足任务。交付应包含有依据的方法理解、关键实验及适用条件；论文存在影响理解的图表时，需要实际阅读并按价值保存，而非一律转成文字。

这是一项任务质量要求，不意味着每篇论文都必须有图片、表格或相同栏目。理论论文、综述和实验论文可以采用不同组织方式。

## 证据与解释

- 明确原文身份和版本，区分论文自述、原文数据、研究者解释与未证实推测。
- 图像截图保留图号、页码等定位；表格转录保留单位、条件、比较对象和来源。
- 上传原文件是保留证据；摘要、OCR 或转录是其派生表示，不能冒充原文。
- 不能读取某项材料时说明缺口，不使用空白块或编造数值装作已交付。
- 用户可以手工补充，也可以让 Agent 提出候选；二者进入同一文献对象模型。

使用行为与验收见 [文献需求](../requirements/literature-node.md)，处理机制见 [内容块模块](../../technical/modules/content-blocks/README.md)。
