# 科研环境的含义

所选科研环境定义研究任务应使用的主机、项目目录和 Python 解释器。它可以来自系统 Python、Conda、venv 或其他已支持来源。

Topolumia 自身的 Node.js 是应用运行环境，不能被当成科研 Python 环境的组成，也不能随科研环境选择而切换。

## 项目工作目录

项目创建以名称和工作目录为入口，新项目 ID 自动生成。用户选择默认工作区、本机已有目录或 SSH 目录。默认工作区是 ~/.topolumia/workspaces 下独立的项目文件夹；本机已有目录内创建 .topolumia，原文件保留。该目录保存项目配置、科研数据库、资产和会话，可随完整项目目录备份和移动。已有项目标识的目录可直接打开，保留原身份和名称。这里的本机指 Topolumia 服务所在主机。

服务器管理员可删除项目，项目管理员和 Agent 不拥有此能力。删除采用逻辑删除：项目退出可访问列表，成员、邀请、Agent 和采集授权失效，研究数据、会话历史与所有工作目录保留；应用内不提供恢复或彻底清除入口。默认项目及最后一个项目同样可以删除，重启不重建已删除项目，账号仍可创建新项目。运行中的任务或请求需结束后再删除。

主机与目录表达科研工作的所在位置，Python/Conda/venv 是该位置上按需选择的运行环境。选择 SSH 目录不隐式选择或安装 Python。SSH 项目的科研数据保存在独立本机项目根/.topolumia，远端保存代码和训练原始记录。账号、登录凭据、全局配置与缓存继续采用用户主目录 ~/.topolumia；项目文件副本不授予原实例的账号权限。

## 查看、检测、选择

展开环境只是在浏览；检测获取对应环境的组件状态；设为当前才改变项目选择。界面与 Agent 上下文必须一致表达这一区别。

选择环境后应检测对应 Python、科研框架、Jupyter、TensorBoard、W&B 等关键组件版本。GPU 驱动、CUDA Toolkit 与框架使用的 CUDA 是不同事实，必须分别呈现；组件缺失或检测失败应显式说明。

所有包及版本属于用户按需查看的诊断能力，不应作为默认 Agent 上下文，也不需要暴露专用 MCP 包清单工具。

## 本机与远程

SSH 连接配置、登录、主机校验、远端目录和解释器选择共同确定远程环境。已有连接配置不代表当前已经登录；查看远端环境不代表当前 Agent 在远端执行。

Agent 获取的是准确、紧凑、有检测时间的环境梗概与执行提示，再自行使用原生工具探索和执行。MCP 不承担通用远程 Shell，也不为每次获取梗概重新探测整个环境。

## 实验记录适配器

实验记录采集是所选主机上的独立能力。用户在工具与环境启用已有记录工具的适配器，平台维护读取环境与后台进程；项目目录及附加范围按项目和主机保存，不随每个实验重新设置。当前训练 Python 环境中的 SDK、外部服务连接与 Topolumia 采集进程是不同状态。

适配器读取和保存来源事实，不启动训练，也不决定实验身份。新 run 按项目发现，用户或 Agent 将其明确归入记录块；一个实验可含多次失败或重试，多个实验可来自同一个采集目录。归属规则见[科研模型](research-model.md#记录接入与复现)。
