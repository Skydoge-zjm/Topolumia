# 科研工作区需求

依据：[科研模型](../business/research-model.md)、[科研变更规则](../business/research-changes.md)。

## 已实现的使用链路

| 研究任务 | 行为与验收 |
| --- | --- |
| 创建、查看研究对象 | 拓扑与详情页使用同一对象身份；刷新、重启后保留人工和已接受内容 |
| 完善文献 | 提供专属核心与自由内容，详见 [文献需求](literature-node.md) |
| 写研究笔记 | 标题与默认正文一起保存；可自由添加内容块和标签 |
| 记录和比较实验 | 统一管理多次 run、归档配置和记录、关联具体材料，临时叠加同名指标曲线 |
| 组织和连接节点组 | 名称、成员角色、多组归属、层级、折叠、组正文及正式组关系，见 [节点组需求](node-groups.md) |
| 建立逻辑联系 | 选择已有节点及关系，保存时检查两端观察到的版本 |
| 接受 Agent 成果 | 先看候选内容与范围，再接受、拒绝或暂缓；结果进入科研历程 |
| 删除节点 | 明确原因与当前版本；冲突后重新核对，更新关联关系与组成员 |
| 回顾研究进展 | 按时间查看人和 Agent 的科研行为，而不是全部工具调用 |
| 管理组会等活动 | 创建纪要、关联节点、记录决策与行动；周期系列可安排具体一期 |

## 一致性要求

- 来源刷新不能覆盖已正式保存的科研对象，默认项目与新项目遵守相同持久化原则。
- 删除后保留必要的历史解释；活动引用有当时的节点快照，不能依赖当前对象始终存在。
- 候选不因持有预留 ID 自动出现在正式拓扑；审批权限在提交时重新校验。
- 活动计划、已发生时间与确认纪要状态应一致；尚未发生的活动不能伪装成已确认纪要。
- 界面语言变化只改变界面文案，不能翻译或修改科研正文。

## 三类节点验收

统一节点组已接入人工编辑、Agent 候选、共享正文和正式组关系。范围、重叠投影与删除验收见 [节点组需求](node-groups.md)。

节点分类和业务边界见 [科研模型](../business/research-model.md)。以下链路已接入人工页面、统一变更和 Agent 候选；实验记录的格式、依赖和读取限制见 [实验与来源模块](../../technical/modules/experiments-and-sources/README.md)。

| 场景 | 必须可观察的结果 |
| --- | --- |
| 创建和检索节点 | 人工入口、Agent 工具与 Schema 统一采用三类节点；自由标签与节点类型分别表达 |
| 保存研究问题或假说 | 可以保存为独立研究笔记，被检索、引用、连接和修订；详细内容由自由内容块承载 |
| 开始写笔记 | 可直接填写标题和默认正文，仍能按需添加、命名和排序多个内容块 |
| 保护未保存正文 | 切换工作区标签或进入核心编辑前确认是否丢弃；取消离开时草稿保持原样 |
| 描述笔记内容 | 可选用自由标签，不要求选择固定的内容性质分类；正文与标签随核心和内容检索 |
| 表达研究角色 | 通过拓扑有向边明确某份笔记被哪个实验采用为前提、由哪个实验检验，以及与哪份解释竞争；节点类型与标签不隐式生成关系 |
| 保存观察、推论与结论 | 来源、条件、推导和适用范围可追溯；自由标签与候选审批不能替代科学验证 |
| 记录实验执行结果 | 实验是可记录、复现一项或一组具体结果的单位；可以只保存结果材料，也可使用记录功能管理失败、重试或复现的多个 run。已有 run 的结果保留对应执行及条件 |
| 保存实验前材料 | 可通过自由内容块上传配置及其他复现材料；项目原文件修改后仍能读取保存当时的内容，无需重复录入一套固定参数表 |
| 查看实验过程 | 复用 W&B、TensorBoard 等已有记录生态，在工作台内渲染原有过程数据与曲线；保留来源，并支持 Agent 读取对应数据，不要求用户接入新的 Topolumia 记录 SDK |
| 在一个块中比较多次 run | 一个 W&B 实验记录块导入三个各含四个指标的 run 后，按指标展示四幅交互式曲线图，各图叠加三个 run 的对应曲线，并能区分各 run |
| 修订过程记录 | 实验记录卡片具备与普通材料相同的编辑、删除和排序入口；删除确认与观察版本校验保持一致 |
| 读取已声明不同横轴的同名指标 | JSON/JSONL 等来源已有明确 xKey 时，step 与 epoch 等系列分别选择、读取和呈现；仅给名称而匹配多个轴时报告歧义，不静默返回另一条曲线 |
| 自由组织多次 run 的材料 | 一张配置表、多份 YAML 或多份日志可以在各自内容块中组织；batch size 调整后的重试可以保留在同一实验中，各次实际条件与失败记录可追溯 |
| 跨材料识别同一次执行 | 配置与日志明确引用记录块/集合及 run；同一记录块内共用执行身份，不同记录块独立 |
| 关联实验内部材料 | 可以明确某份配置文件、配置表中的记录或日志对应曲线块中的哪个 run；支持跨内容块关联到具体材料项 |
| 跨实验查看比较 | 人或 Agent 选择实验 A 的 run 3 与实验 B 的 run 1 后，只允许名称完全相同的指标曲线临时叠加查看，保留原实验、run 和来源；比较不保存为对象或内容块，原始记录不因比较而改变 |
| 匹配叠加指标 | 内容块内与跨实验比较采用完全同名规则，不提供不同名称指标的对应选择或语义匹配 |
| 保存实验分析 | 人或 Agent 需要保留分析时，在新建的研究笔记节点中记录；Agent 沿用候选与人工审批机制 |
| Agent 分析实验 | 能读取内容块中的多 run 数据及配置、曲线、日志之间的对应，明确分析的是哪次执行和哪些记录项 |
| 整理最终结果 | 通过指标、表格、TeX/PDF 等已有内容能力组织最终数据及概要，保留对应 run、条件和来源 |
| 统一已有实现 | 类型调整覆盖正式对象、候选、检索、拓扑与历史；保留已有真实内容、资产、关系和引用，不通过清空数据完成切换 |

配置表既可为内联表格，也可为上传的 XLSX、CSV 或可解析 TeX 表格。关联保存块版本、文件身份及具体行；后续编辑当前块不会改写已保存的关联。预览不完整时从归档原文件读取所选行，不能把预览行号当作全部数据。

## 实验记录块归属

实验节点是实验身份及自由材料容器；过程工作台由可选的实验专属内容块承载，业务定义见[科研模型](../business/research-model.md#实验与-run)。工作台已经归入可选记录块；节点默认使用自由材料布局，运行目录与材料引用由具体记录块管理。

| 场景 | 必须可观察的结果 |
| --- | --- |
| 只保存实验结果 | 创建实验节点后直接上传一组表格、图片或指标即能完成记录；无需创建 run、配置来源或处理空的运行工作台 |
| 按需启用过程工作台 | 添加实验记录块后才在该块内或其展开视图中出现 run、曲线、数据和快照功能；环境页统一管理采集；节点不强制常驻运行栏或全局原始数据页 |
| 一个或多个记录块 | 一个块可含多个 run；多个块分别管理自身选择；可明确选择同一项目来源，数据只保存一次，同名执行不自动合并 |
| 关联其他材料 | 配置、表格行和日志引用具体记录块中的 run 及材料版本；其他材料块无需因此变成实验记录块 |
| 从节点进入比较 | 解析到节点中实际可比较的记录块，保留块/run 来源；无过程记录时说明范围，不生成虚构 run，也不把普通表格自动转成曲线 |
| 编辑、归档及再读 | 普通块操作仍可用，归档记录块不误删历史、附件或显式共享数据；持续数据版本与块显示/绑定修订分开 |

## 持续接收

使用流程为“工具与环境启用采集 → 项目自动发现运行 → 选择归入实验记录块 → 持续查看”。托管部署、项目记录目录、运行选择和专属目录自动归入已接入原生解码、持久队列、富记录查询与固定快照。格式边界见[实验模块](../../technical/modules/experiments-and-sources/README.md#当前格式范围与已知缺口)。只保存结果材料的实验无需启用采集；平台不修改训练参数、不启动或调度训练。

| 场景 | 必须可观察的结果 |
| --- | --- |
| 首次启用 | 在工具与环境选择已连接主机，点击 W&B/TensorBoard“部署并启用”；平台安装独立读取环境、启动后台进程、建立传输和授权，正常路径不下载脚本、不填地址或 token |
| 默认记录位置 | 继承该主机的项目目录，在受限范围内增量识别原生记录；附加目录按项目和主机记住，不按实验重复配置 |
| 准确报告状态 | SDK 包、适配器进程、传输和数据新鲜度分别报告；历史接收不能证明在线，没有新点不推定训练结果 |
| 新建记录块 | 添加“实验记录”后直接选择已发现 run 或导入已有文件；选择来源决定工具类型，不重复填写；空块直接显示两种入口 |
| 尚未启用采集 | 记录选择界面提供启用入口，沿用环境页部署能力；完成后返回原实验，不丢失选择和草稿 |
| 先训练后整理 | 未绑定 run 出现在项目“未归入实验”视图，选择多项后加入已有实验或创建实验；保留名称、主机、工具、来源目录、状态和接收时间 |
| 多次尝试 | 一个块可选择多个失败、重试或复现 run；选择不会改变源数据，不以文件名或显示名猜测实验归属 |
| 后续自动归入 | 用户可对明确的专属子目录设置后续归入；规则可查看、关闭，公共采集根目录不作为默认归组规则 |
| 多块隔离 | 项目源记录只存一份，块保存明确选择；曲线、事件、附件、目录及固定快照不得混入未选 run；相同来源可被显式选择到多个块 |
| 移除和暂停 | 移除 run 只改变块归属，归档块不停止环境采集；暂停或撤销采集保留已收数据及本地队列 |
| 日常查看 | 块中提供曲线、事件与附件、运行与材料、数据表；添加运行和固定当前版本可直接操作，部署和授权集中在环境页 |
| 同机与远程 | 本机托管进程，远程复用 SSH 主机配置并由平台维护传输；关闭浏览器不停止，工作台离线时源端排队，恢复后续传 |
| 记录增长与重启 | 源端落盘后增量更新；ACK 丢失重传幂等，真实重复或回退 step 保留，容量不足暂停读取并反馈；恢复沿用身份与游标 |
| 原生语义与文件 | 保留 dtype、自定义横轴、配置/摘要更新、表格/分布、生命周期、restart 和未知扩展；附件独立传输，缺失、超额和不支持预览明确反馈 |
| 固定结果 | 保存块版本、所选运行、各来源水位及材料版本；后续追加或修改归属不改变固定依据，人和 Agent 使用同一读取路径 |
| 统一事后导入 | 单次导入与持续接收复用事件语义和查询，文件导入继续保留原件及依赖；高级插件保真保存不承诺原生交互渲染 |
| 授权边界 | 管理采集需要项目管理权限；接收身份只允许指定项目来源追加与附件提交，不能修改实验归属、节点、分析或候选；人工归组走科研变更，Agent 沿用候选审批 |

验收使用真实 W&B/TensorBoard 写入器和 WSL SSH 主机，覆盖一键部署/暂停/恢复、默认目录、多个实验共享采集目录、块级选择隔离、明确规则后续归入、重启、离线积压、富事件、附件和固定快照。原生日志按完整前缀分段归档，单附件 64 MiB，默认待发额度 128 MiB；云服务、完整 autolog、DDP/shared 和多机训练行为分别验证。方法见[测试指南](../../playbooks/testing.md#实验生态记录调研)。

## 其他边界

服务来源可能已采样，应保留来源提示；当前完整点读取只对归档中实际存在的数据作保证。不同名称指标的语义匹配暂缓。

多人实时共同编辑、完整撤销体系和跨项目科研对象协同尚未承诺为当前完成能力。

机制：[节点模块](../../technical/modules/research-nodes/README.md)、[节点组模块](../../technical/modules/node-groups/README.md)、[变更模块](../../technical/modules/research-changes/README.md)、[研究记录模块](../../technical/modules/research-records/README.md)。
