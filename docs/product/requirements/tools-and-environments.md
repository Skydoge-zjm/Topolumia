# 工具、环境与 SSH 需求

依据：[科研环境业务](../business/research-environment.md)。

## 环境选择流程

1. 先选择本机或已有 SSH 主机；SSH 管理是明确按钮，不混入主机选项。
2. 按 Python、Conda、venv 等来源逐级展开，再查看具体环境。
3. 展开、检测与“设为当前”分别触发不同动作，不因浏览而改变当前选择。
4. 设为当前后检测对应关键组件，显示版本、路径、检测时间与失败原因。
5. 通过单独入口按需查看所有包及版本；不把包清单平铺在主页面。

下拉框沿用现有 SelectMenu。环境信息尽量紧凑，细节逐级展开；应用 Node.js 状态与科研环境明确分区。

## SSH 链路

已有别名或手动连接配置均可进入管理。登录支持实现范围内的凭据、主机校验和挑战处理；连接结果、远端目录和环境归属要可见。凭据保存方式与会话登录状态不能混淆。

远程探测当前面向 Linux、WSL 和 macOS。WSL 可用于开发验证，但机器专属别名不能成为运行前提。

## 给 Agent 的上下文

通过 get_environment 返回当前选择的紧凑梗概：主机、目录、解释器、关键组件、资源概况、缓存时间与可用性。缺失、过期或尚未连接的状态要明确表达。

该读取不触发新的大范围环境探测，不返回全部包，不替 Agent 执行通用命令。Agent 按提示用自己的工具进入目标环境。

## 验收与边界

- 切换环境后组件版本来自新解释器，不能沿用旧缓存冒充检测结果。
- 区分 GPU 驱动、Toolkit 和框架 CUDA，不能拼出一个含义不明的“CUDA 版本”。
- 普通展开不改变已选环境；查看其他主机不会自动转移当前项目绑定。
- Node.js 服务使用的运行时不随科研环境切换。
- 当前已有选择、探测、包列表、SSH 与梗概实现；远程 Agent 调度、训练资源预留和自动部署不在当前交付范围。
