# Agent 工作台需求

依据：[Agent 协作](../business/agent-collaboration.md)。Codex、Claude Code、OpenCode 使用共同工作台；原生能力有差异时明确反馈，不另造三套会话界面。

## 会话与控制

- 创建、继续、切换会话时保持用户消息、历史内容与会话身份；新回合追加到原会话。
- 执行中可停止；输入为空时发送位置显示停止按钮，有新输入时允许排队，展示队列与失败恢复。
- 输入框支持以 `/` 开始的 Agent 命令。菜单只显示当前 Agent 在 Topolumia 中可执行的命令；未知命令不能静默当作普通提示词发送。
- 命令与普通消息遵循同一会话队列、幂等提交、SSE 事件和历史保存规则。命令执行显示开始、完成或失败状态，原始命令名与参数保留在会话事件中。
- 当前统一支持 `/compact`：Codex 通过 App Server 压缩 thread，Claude Code 通过非交互会话命令压缩上下文，OpenCode 2 通过原生 session compact API 压缩会话。Codex 另外提供 `/review`、`/rename`、`/goal`，OpenCode 2 提供 `/undo`、`/redo`、`/fork` 及已发现的项目命令。压缩和其他命令不能绕过正在运行的回合；排队后按原顺序执行。
- 终端界面设置、账号管理、权限修改、外部控制和破坏性操作不作为普通 Web 命令提供。OpenCode 1 仅保留既有能力，不进入新的命令功能范围。
- 不设置整个研究任务的统一倒计时；应用进程意外结束后保留历史并解释中断。
- 会话容量只限制运行实例，归档、关闭和重启不按数量裁剪保存历史。
- 保存失败可见并可重试，不把未落盘误标为保存成功。

## 紧凑且可探索的展示

- 最终回复提供复制和保存科研笔记操作，中间回复不重复这些按钮。
- 推理、命令、MCP 等类型有不同图标；连续过程可折叠为按类别计数的一行摘要。
- 命令或 MCP 调用未展开时每项一行；逐项展开后命令、输入、输出各在有限高度内滚动。
- Topolumia 自有工具采用中英文语义名称；外部 MCP 不强行改名。结构化结果按结构展示，复制保留完整原输出。
- 连续 imageView 合并为图像组，展开显示缩略图，点击看大图并可关闭；临时文件消失后历史图像仍可查看。
- 用户可粘贴或选择受支持图片，发送给原生 Agent；草稿图片可以移除。
- 会话消息导航可定位用户消息并提供悬浮摘要；动效克制，支持减少动态效果。

## 两种审批

原生执行审批显示动作、范围和可选决定，按当前权限禁用不可用选项；与正文对齐，使用普通字体。Agent 原生提供的选择可以不同，但不可绕过应用的高风险审批权限。

科研候选在所属回合结束处显示可交互审批卡，支持预览、接受、拒绝和暂缓；没有权限时明确说明，Agent 不可自批。

## 配置

统一配置页通过引擎选项卡展示选中 Agent 的运行时状态，并在页内提供常用设置、完整配置项和原生文件编辑。三种编辑视图共用一份配置草稿。Codex 使用 TOML，Claude Code 使用 JSON，OpenCode 使用 JSONC。保存到项目根/.topolumia/agent-config，新会话使用配置快照，配置与会话历史随完整项目目录保存；不能暗中覆盖用户主目录的全局配置或登录凭据。

OpenCode 提供“OpenCode 2”和“OpenCode 1（旧版）”两个独立入口。V1 保留现有能力并冻结，后续优化和维护集中在 V2。两版原生配置、权限和默认模型独立保存；会话继续与历史同步遵守原有版本归属，不因 CLI 升级而改变。版本不匹配时显示安装版本及恢复建议，已有历史仍可阅读。OpenCode 2 的保存授权属于项目级规则，审批必须明确其对后续会话的影响。

## 实现状态与差距

上述主链路已有实现与工程测试。原生事件和审批覆盖取决于具体 CLI 版本；工程样例通过不等于所有模型、版本与真实长任务都已验证。后续适配需保留明确的未知事件处理与原生错误信息。
