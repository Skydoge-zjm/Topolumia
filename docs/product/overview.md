# 产品目标与边界

Topolumia 为需要阅读文献、复现实验、比较证据并与 Agent 协作的研究者提供本地优先的科研工作台。核心价值是把研究成果留下来，形成可探索、可修订、可追溯的科研对象，而不只是保存一次聊天。

## 用户工作

- 阅读真实论文，保存书目信息、方法理解、关键图表、指标和疑问。
- 以文献、实验和研究笔记组织科研内容；笔记承载问题、假说、观察、分析和结论，并通过关系表达研究逻辑。节点组组织紧密相关对象，也能作为整体关联设计、总结与其他研究内容。
- 让 Agent 读取必要上下文、推进任务、提出有内容和来源的候选变更，由研究者审阅。
- 选择本机或 SSH 科研环境，让人和 Agent 知道应使用哪个解释器与工作目录。
- 通过研究记录回顾操作历程，整理组会、阅读和周期活动。

## 产品原则

研究者决定内容如何组织。类型核心提供最小结构；系统定义内容块能力，不预置强制栏目和研究步骤。未知信息可以留空，不能制造事实。

Agent 与人类共享科研对象的含义，但权限不同。执行工具获准不代表其科研结论已被接受；候选被接受不代表实验结果已经过科学验证。

逻辑拓扑、时间活动、执行日志和普通笔记承担不同职责，不能因为都能显示文字就合并为一种记录。

## 当前交付范围

已实现本机 Web 应用、账号与项目权限、三种 Agent 接入、MCP 科研接口、自由内容块、文献专属核心、候选审批、研究历程、环境检测与 SSH 管理，以及实验来源适配。

节点统一为文献、实验、研究笔记三类。文献提供书目核心；笔记提供默认正文、自由标签与扩展内容块；实验提供统一 run 清单、归档记录、多 run 交互曲线及具体材料关联。人和 Agent 均可临时比较不同实验的同名指标，分析保存在新笔记中。读取范围与尚未交付能力见 [工作区需求](requirements/research-workspace.md)。

统一节点组支持独立正文、成员角色、层级、正式关系端点、主边及 Agent 候选，使用与验证范围见 [节点组需求](requirements/node-groups.md)。

已有权限能力为团队演进提供基础，但互联网生产部署、远程 MCP、完整协同冲突体验和托管训练调度尚未交付。本机 SSH 检测不意味着 Agent 自动迁移到远端运行。
