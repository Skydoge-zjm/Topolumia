# 排查 Agent 会话与科研交付

先区分执行失败、展示错误、持久化错误与成果质量问题。不要先修改提示词、延长统一倒计时或全量重跑模型。

## 定位最小事实

确定项目、工作台会话、研究会话、原生会话和回合身份；记录提供商及实际版本。读取失败前后的必要事件、最终错误与候选状态，不默认导出全部历史。

| 现象 | 优先检查 |
| --- | --- |
| 上半段正文消失或继续后像新会话 | 原生 ID → 统一消息身份 → HTTP/SSE 合并 → 前端投影 |
| 多次思考被拼接 | 消息/内容段边界、绝对快照与 delta 区分 |
| 任务突然停止 | 原生退出、用户停止、连接错误；不要增加应用整回合限时 |
| 画面有内容但重启丢失 | persistence 状态、检查点错误、实际历史库位置 |
| 候选没有显示审批卡 | 工具真实回执、研究会话绑定、candidateTurns 与 ETag 刷新 |
| 接受后只有基本信息 | 精确读取候选块目录与正文，确认 Agent 是否实际提交成果 |
| 论文只有文字、没有图表 | 检查原文是否存在必要图表、是否实际查看、是否传输并绑定，不能强行给所有论文凑图片 |
| 环境用错 | 查看当前环境梗概、缓存时间、主机与解释器，核实原生工具实际命令 |

## 上下文与效率

统计工具目录、Schema 查询、正文、终端输出、重复读取、错误和重试的总成本。分开看返回字符/字节与模型输入 token；未取得真实 usage 时不能把字符数称为 token。

检查核心证据是否进入上下文、是否形成有内容的候选，而不只看 MCP 输出变短。固定测试与真实研究任务分开，记录模型、版本和场景，避免将单次运行结果推广到所有宿主。

## 修复与验证

协议问题在 [适配层](../technical/modules/agent-workbench/trace-adapters.md) 修，合并在前端模型修，科研交付合同在 [接口架构](../technical/architecture/agent-integration.md) 与 [变更模块](../technical/modules/research-changes/README.md) 修。不要用前端字符串补丁掩盖后端身份问题。

先用最小原生事件或隔离科研对象复现；定向检查通过后，只有确需验证模型理解或原生实际行为才运行真实任务。报告包含问题、根因、改动与验证范围，临时原始资料在审阅完成后清理。
