# 扩展一种内容能力

先判断它是新的内容语义，还是已有类型的新文件表示。XLSX、TeX 和截图都可能表达同一张表，不应每增加扩展名就新增一种节点或内容块类型。

业务依据：[科研模型](../product/business/research-model.md)。机制入口：[内容块模块](../technical/modules/content-blocks/README.md)。

## 开发顺序

1. 明确研究者要保存、查看、编辑和导出的材料，以及必要来源信息；不强制新增研究栏目。
2. 核对 [Schema](../../src/domain/research/content-blocks.ts) 与表示模型，定义最小结构和未知/不可用状态。
3. 接入领域校验、精确读取与变更规则；如有文件，明确原件、派生物和绑定生命周期。
4. 在渲染器实现真实阅读效果，在编辑器实现最小 patch，取消和切换不产生隐式写入。
5. 需要 Agent 操作时扩展共享工具/Schema 合同，不创建独立 MCP 或 CLI 写入实现。
6. 更新相关需求与模块说明，按影响选择验证。

## 必须思考的边界

- 只有文件、没有内联 payload 时能否正常保存和显示？
- 重命名会不会丢失条件、来源、样式或高级配置？
- 预览是全量还是截断，是否能明确区分？
- 解析失败时原件是否保留，界面是否说明原因？
- 多次重试、候选修订和接受是否保持相同对象身份？
- 是否仍遵守项目权限、版本冲突和科研正文原文保护？

验证应包括有价值的往返与边界，而不仅是渲染了一个标题。文件能力使用真实小文件，必要时在浏览器检查；普通文案修改不重复运行这些流程。命令见 [测试指南](testing.md)。
